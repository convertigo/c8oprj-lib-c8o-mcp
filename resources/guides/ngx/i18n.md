## Add a translation

1. Follow the app's dictionary layout and language selection. The standard Mobile Builder loader reads `./assets/i18n/<lang>.json` from the project-owned `DisplayObjects/mobile/assets/i18n/` dictionaries. Projects with root-level `i18n/<lang>.json` need explicit build assets and an app initializer to load or merge them into `TranslateService`. Update the tracked dictionaries in the location the app uses. Use Studio or the project's authorized file workflow for these source JSON assets. Studio can seed a standard dictionary with Create or update translations file. The project-js tools only handle JavaScript under `js/`.
2. Add one stable, feature-scoped key per new message to every supported language. Use the project's naming convention. For new `UIText` keys, use short ASCII letters, digits, underscores or hyphens, at most 40 characters. Mobile Builder replaces other characters with underscores and truncates to 40. Keep accents in the translations and keep interpolation parameter names identical across languages.
3. Set `i18n: true` and put the unquoted key in the PLAIN `textValue` of the `UIText`. For example, use `{i18n:true,textValue:{mode:"PLAIN",value:"Orders_Title"}}` in its tree properties, with `{"Orders_Title":"Orders"}` in `en.json` and `{"Orders_Title":"Commandes"}` in `fr.json`. The builder emits the translate pipe for PLAIN text when it finds a language dictionary in the standard directory. For SCRIPT text or a bound label, supply `'Orders_Title' | translate` as the Angular expression. In shared-component bindings use single quotes around the key inside a double-quoted HTML attribute, for example `[attr.aria-label]="'Orders_Title' | translate"`. In single-quoted Convertigo YAML strings or formatted content, double the inner single quotes once. In MCP property values and Studio enter the actual expression.
4. In page or shared-component TypeScript use `this.translate.instant('Orders_Title')` after the active dictionary has loaded. Use `this.translate.get('Orders_Title')` when loading may still be in progress, or the pipe for UI that follows language changes. In an action use the page's `TranslateService` (for app-level actions, import it from `@ngx-translate/core` and get it with `page.getInstance(TranslateService)`). Keep the app's existing language action or call `translate.use(lang)` at initialization and on language changes. With `SetLanguageAction`, align `supportedLanguages`, `fallbackLanguage`, and the selector with the shipped language files. Preserve the app's stored-language behavior and await custom dictionary loading before language selection.
5. A visible key usually means the key is missing, was normalized by the builder, or the language file failed to load. Run `project-lint` and check the rendered text in the default language and after switching languages. For custom dictionaries, check parity and interpolation parameters in CI and verify their contents in the built archive. Lint reads the standard dictionary path and does not see arbitrary custom loaders.
