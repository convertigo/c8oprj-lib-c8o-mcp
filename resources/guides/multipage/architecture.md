## Architecture
1. Project from `marketplace-import({project:"template_ngxBuilderIonic", importedProjectName:"<App>"})`.
2. One `SqlConnector` for the application database (HSQLDB file database is enough for a V1 and a demo). Create it and its transactions new: the starter's `void` connector holds a placeholder `void` transaction whose `onTransactionStarted` handler returns `cancel`, so a renamed or reused copy runs nothing and still answers ok. `databaseobject-tree-get` shows a transaction's JavaScript `handlers`; `handlers:""` in `databaseobject-tree-apply` removes them. For an HSQLDB file database set `jdbcDriverClassName` `org.hsqldb.jdbcDriver`, `jdbcURL` `jdbc:hsqldb:file:.//database/<app>;shutdown=true` (relative to the project folder), `jdbcUserName` `sa` and an empty `jdbcUserPassword` (the exact property names; `palette-describe` lists them), and leave the connection testing query `systemTablesQuery` empty (HSQLDB refuses `SELECT 1` without `FROM`, which breaks every connection); never write `${...}` in a property value, Convertigo reads it as a global symbol. HSQLDB DDL that works: `id INTEGER GENERATED BY DEFAULT AS IDENTITY (START WITH 1) PRIMARY KEY` (without `START WITH 1` HSQLDB numbers from 0, and a seed that references id 1 gets the wrong row), `DEFAULT` before `NOT NULL` (`actif BOOLEAN DEFAULT TRUE NOT NULL`), several `CREATE TABLE IF NOT EXISTS` statements separated by `;` in one transaction.
3. One `SqlTransaction` per statement: `q_*` for reads, `w_*` for writes. Alias every selected column with a quoted camelCase name (`id AS "id"`): HSQLDB upper-cases unquoted names in `sql_output`, and the business sequences read these keys. An optional filter is `({x} = '' OR col = {x})` on a text column and, on HSQLDB, `({x} = '' OR col = NULLIF(CAST({x} AS VARCHAR(4000)), ''))` on a number, date or boolean column (the bare form logs a WARN on every call without the filter): an absent variable arrives as an empty string, never NULL. A write that must be atomic across several statements is one transaction with several queries separated by `;` and `autoCommit` `2` (enabled, once at the end). `palette-describe` lists the codes in `allowedValues`.
4. Business rules in one `js/app.js` file written with `project-js-set({project:"<App>", filename:"app.js", ...})`: constants, date and status computations, validation, response builders. Hang everything on one object (`var App = (function () { ... return {...}; })();`). `js/app.js` is where `business-sequence-create` reads the rules by default; another file needs `script:"js/<file>.js"` in each call.
5. One business sequence per service, all with the same response contract `{success, data, errors:[{code,message,field}], meta}` emitted by `JsonToXmlStep` steps.
6. Configuration in global symbols `${app.setting=default}`; secrets in `.secret` symbols without default. The engine resolves `${...}` only in object properties, such as a `SimpleStep` expression, never inside `js/*.js`: pass the settings from the first step of each sequence, `app.configure({delayMonths: "${app.delayMonths=2}"})`, and keep the values in the shared object. In JS, `Engine.theApp.databaseObjectsManager.symbolsGetValue("app.delayMonths")` returns the stored value or `null`, without the inline default.
