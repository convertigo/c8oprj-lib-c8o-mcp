# QNames, source priorities and precise readback

Read when: QNames, source priorities and precise readback. Summary: `convertigo://guides/common`.
Previous: `convertigo://guides/common/batching`. Next: `convertigo://guides/common/progress`.

---

- Copy QNames from `databaseobject-tree-get` or `databaseobject-search` output instead of building them: only the first level carries a type prefix, a nested step is `<Project>.sq:<seq>.st:<ifStep>.<step>` (no `st:` on the nested step).
- Prefer the tree shortcuts, expanded by the MCP into ordinary objects: an NGX SmartType `{"mode":"SOURCE","local":"?.results"}`, `{"mode":"SOURCE","global":"?.currentUser"}` or, in a form's submit action, `{"mode":"SOURCE","form":"email"}` (the value of that control of the enclosing form) (optional `prefix`/`suffix`) instead of the full Local/Global/Form picker JSON; a node key `attributes:{"class":"card","[hidden]":<SmartType>}` instead of one `UIAttribute` child per attribute; an event or action key `setLocals:{"loading":"false","items":"[]"}` (SCRIPT expressions) instead of one `SetLocalAction` per local; `importVariables:true` on a `TransactionStep` or `SequenceStep` instead of one `StepVariable` per variable of the called requestable. An explicit child with the same name wins. In sequences, source a step by name instead of by priority: `sourceDefinition:{"step":"callMe","xpath":"./document/sql_output"}` or a SmartType `{"mode":"SOURCE","step":"callMe","xpath":"./document"}`; the step must exist before (an earlier sibling in the same tree works), so one tree-apply creates and wires a whole sequence.
- For a business app, build the standard objects with the generators before writing trees: `sql-transaction-create` (SQL transactions, several per call), `business-sequence-create` (a business sequence from {name, inputs, roles, reads, writes, logic function of js/app.js}; reads and writes call SQL, a transaction of any connector such as HTTP, or a sequence of a referenced library) and `ngx-page-create` (list, detail, form, dashboard or logout page; a table list of 5 cells or more is the agGrid of `lib_ExtendedComponents_ui_ngx`, imported for you; an app that signs users in gets a logout page in its menu), after `ngx-theme-apply` (the app's colors, toolbar, spacing and light mode, from the user's brand color and a preset). Each validates its spec, creates all or nothing and returns the created QNames; `convertigo-recipe-multipage-app` says when to use `databaseobject-tree-apply` instead.
- For `databaseobject-tree-get`, use `childrenDepth` for recursive descendants and request the needed subtree once instead of walking one QName level per call. `depth` is accepted only as a compatibility alias.
- `databaseobject-tree-apply` always takes the target QName in `target`, never in `qname`. `at` defaults to `"self"`, which patches the target itself: creating or updating a child needs `at:"inside"` on the parent, and a self patch whose tree names another object is refused. With `at:"inside"`, `tree` is the one concrete child being created and must include its own `className` and `name`; never submit a children-only wrapper. Put sibling creations in separate calls or batch entries. If a child with the same name already exists, the same class is updated in place (with a warning) and another class is refused; the engine never silently creates `<name>1`. Writing `sqlQuery` declares the `{variables}` of a `SqlTransaction` at once, so `importVariables` on a calling step sees them. A transaction's JavaScript handlers are the node key `handlers` (shown by tree-get, written by tree-apply, `""` removes them), not a property.
- Property patches also belong under `tree`: use `databaseobject-tree-apply({target:"<qname>",mode:"merge",tree:{properties:{isEnabled:false}}})`. Never send `properties` beside `target`, because top-level `properties` is not a tree-apply argument.
- `databaseobject-tree-apply` with `mode:"replace"` and an empty or qname-only `children` does not delete anything. Delete exact nodes with `databaseobject-delete` and read back the parent to require the QName is absent.
- `mode:"merge"` updates properties but does not remove stale incompatible properties. When repairing an object whose shape changed, read it back and delete/recreate it if an incompatible property remains.
