# Act on verifier reports and close the task

Read when: Act on verifier reports and close the task. Summary: `convertigo://guides/common`.
Previous: `convertigo://guides/common/proof`. Next: `convertigo://guides/common/seed`.

---

- Acting on the report (`report` of `subagent-run`, the top level of `browser-verify`): `verdict:"passed"` closes the proof; quote its evidence and screenshot paths. A `failed` check or a visual defect is a finding about the app: fix it in the source objects, rebuild, then call `browser-verify` again for the affected paths only. The sub-agent can be wrong: when a check is `not_checked`, or its evidence contradicts what you know of the data, read the named screenshot with `image-describe` or make one targeted Playwright check yourself before changing code. Never rerun the same verification unchanged to get another verdict. The sub-agent only observes and never edits the project: the decision and the fixes stay yours.
- Without a verifier (the tool is missing, or it reports no viewer or a gateway error), prove each path with the dedicated Playwright tools: `browser_navigate`, `browser_snapshot`, `browser_fill_form` (all the fields of a form in one call), `browser_click`, `browser_evaluate` (the values of a page read in one call) and `browser_take_screenshot` with `filename: ".playwright-mcp/<page>.png"` on each page; fix and retry the path when a check fails. In the Studio viewer, three things make a click wait 30 s and fail: the Studio's build progress widget (a `div` holding a 100x100 `canvas`, centred on the page) takes the clicks above Ionic overlays, so start each path with one `browser_evaluate` of `() => document.querySelectorAll('body > div').forEach(d => { if (d.firstElementChild && d.firstElementChild.tagName === 'CANVAS') d.style.pointerEvents = 'none'; })`; an `ion-select-option` is never visible, so click the `ion-select`, then the option text in the alert or popover it opens, then the alert's OK; and an `ion-input` is filled through its inner `input` (`ion-input input`).
- To look at one screenshot when your model cannot read images (it has no image input, or a screenshot is refused): save it with `browser_take_screenshot` and a `filename` (with a filename the image is only saved, not sent to your model), then call `image-describe({path:"<the file>", question:"<what to check>"})` with one precise question. Keep the default `reasoning` (none) and `maxTokens`; one call per page state is enough.
- A single hydrated DOM sample proves only that the viewer rendered that state. For timers, live updates, interactions, or other changing behavior, require two observations showing the expected change or an equivalent browser-control assertion.
- If browser control is unavailable, report the result as implemented but functionally unvalidated. Do not claim success merely because compilation and server logs are green.
- Stop after the requested behavior is green. Do not add an unsolicited polish pass, do not restart broad verification, and do not repeat proof that cannot change the conclusion.
- When the MCP lists `report-create`, the user agreed to send feedback to Convertigo: file at most one short report per turn for a reusable friction of a Convertigo tool, guide or prompt that you had to work around (what you expected, what happened, how you got past it). Never report your own mistakes or a refusal you fixed at once, and never put project data, names or credentials in it.
