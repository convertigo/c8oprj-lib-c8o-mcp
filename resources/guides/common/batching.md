## Tool economy and convergence

- Treat every tool round trip and large response as part of the task cost. Prefer targeted reads and request only the depth, properties, logs, or detail needed for the next decision.
- Do not repeat catalog, guide, palette, tree, builder, or browser reads whose answer is already present in the current conversation.
- In a sequence, wire a step to a step created before it, in the same tree or earlier, by its name: `sourceDefinition:{"step":"<step name>","xpath":"./document"}` (also `["<step name>", "<xpath>"]`), a SmartType `{"mode":"SOURCE","step":"<step name>","xpath":"./document"}`. The MCP fills in its priority: never look for priorities or ids before writing a sequence.
- Use `palette-list` to locate an unfamiliar object type and `palette-describe` only for properties that remain uncertain. Call `palette-list` with the exact intended parent QName as `target` and pass its returned logical `className` unchanged to `palette-describe`. Do not list at project scope and guess a `#logicalId`. An NGX palette name is written in full, `ngx.components.<Class>#<logicalId>` (`ngx.components.UIDynamicElement#Button`, `ngx.components.UIDynamicAction#CallSequenceAction`, `ngx.components.UIText#UIText`): never an HTML tag (`ion-button`), an `Ion` or `UI` prefix, or a name of your own. When a palette tool answers `not found`, take one of the close entries it lists instead of guessing again.
- A class/property shape already used successfully in the current conversation or returned by a targeted tree read is a confirmed contract. Do not reconfirm it through palette calls or tool-metadata inspection.
- Common NGX contracts that do not require palette discovery are `UIStyle#UIStyle.styleContent`, `UIAttribute#UIAttribute.attrName/attrValue`, `UIDynamicElement#TextItem`, `UIText#UIText.textValue`, `UIPageEvent#UIPageEvent.viewEvent`, and `UICustomAction#UICustomAction.actionValue`.
- For a fresh starter UI that uses only local page state or static content, one exact entry-page tree read is enough discovery for those common contracts. Skip `palette-list` and `palette-describe`, then perform the first coherent mutation immediately.
- Reuse before building (bootstrap step 5). `marketplace-list({search:"<capability>"})` lists first the libraries that provide a capability word, with their `use`; when nothing matches, `suggestions` gives the closest entries. `marketplace-describe({project:"<library>"})` returns its readme: what it does, its sequences and variables, its shared components and the setup it needs. `marketplace-import({project:"<library>", targetProject:"<your project>"})` adds it and the reference to it in your project; then `marketplace-describe` again gives the exact QNames of its sequences and shared components: call them with `SequenceStep` or `CallSequenceAction`, place its shared components in your pages.
- Build one coherent mutation plan before the first write, then perform one targeted readback.
- A tool answer may start with two fields. `operatorNote` is a note from the person who supervises your work, sent while you work: read it as a user message and follow it from your next step. `argumentWarning` names arguments the tool does not take: the call ran without them, so call it again with the arguments it lists.
- Output tokens are the main cost of a build. When you generate a large batch with a script or a file, do not paste it back as `calls`: write the calls array as a `.json` file in the temporary folder of this conversation (each turn names it: `Temporary folder of this conversation: <path>`; without that line, a folder under the projects workspace; never the workspace or project root) and call `batch-call({callsFile:"<absolute path of that file>"})`. The path is absolute, or relative to the projects workspace; `calls` and `callsFile` are exclusive. A later call can reuse an earlier call's result with `{"$ref":"<callId>.<path>"}` (or the string `"$ref:<callId>.<path>"`), where `<callId>` is the `id` given to that call and `<path>` walks its payload, for example `{"$ref":"readSeq.tree.priority"}` after a `databaseobject-tree-get` with `id:"readSeq"`. For a shared script, write the file in that temporary folder and call `project-js-set({project, filename, contentFile})`; the response never echoes the content.
